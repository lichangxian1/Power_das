# approx_mul16_cu — 纯截断 Dadda 树 16-bit 近似乘法器库 (CUDA 功能模型)

10 个 16×16 近似乘法器,MRED 从 ~1e-5 到 ~1e-1 近似对数均匀覆盖,用于 AI
应用误差注入测试。全部为**纯截断 Dadda 树** (truncated Dadda multiplier):
把 32 列部分积矩阵中最低 K 列的部分积直接丢弃(无任何误差补偿),其余部分
积用 Dadda 树精确压缩求和。因为保留部分的归约是精确的,功能级模型就是:

```
P = Σ_{i=0..15}  a_i ? ((b << i) & (0xFFFFFFFF << K)) : 0
```

注意这**不等于** `(a*b) & ~((1<<K)-1)`:截断发生在部分积生成阶段,被丢弃
的低列不再向高位产生进位,所以误差比"结果截断"更大,且恒为非负
(近似值 ≤ 精确值,单向偏小)。

归一;ER 为出错概率。

## 接口(工具固定签名,不可改)

每个 .cu 是 `namespace app` 包裹的 `__device__` 代码,入口为:

```c
namespace app {
__device__ uint32_t dadda16u_trunc(uint16_t a, uint16_t b);  // 无符号核心
__device__ int32_t  int_mul(int32_t a, int32_t b);           // 工具调用入口(固定)
}
```

`int_mul` 按符号-幅值包装:负数取绝对值送核心后恢复符号,非负输入
(含 uint 量化码 0..65535)原样进核心。要求 |a|,|b| ≤ 65535。
两个无符号码都接近满幅时精确积超出 int32 正范围,返回值按补码回绕。
一次只把一个 .cu 交给工具(10 个文件的 `app::int_mul` 同名)。
`mul16_exact_probe.cu` 是同接口的精确乘法探针,用于区分工具问题和乘法器问题。

**注意**:上表 MRED 是无符号均匀输入口径(近似乘法器文献的标准口径,如
EvoApprox)。若你的工具在均匀 int16 输入上测有符号版本,因平均幅值减半,
实测 MRED 会大 ~3 倍(例如 t08 约 3.1e-5);如需在有符号口径下对齐
1e-5~1e-1,把每档 K 减 2 即可(mask 是文件里唯一的参数,直接改 `<< K`)。

## w11/ 子目录:适配工具"权重 11bit"上限的重标定档位

实测(2026-07-11)误差注入工具的 16bit 路径在权重位宽 ≥12 时数值溢出
(精确乘法探针在 W=11 得 94.05%、W=12 掉到 11.54%,与近似乘法器结果
几乎相同,证明是工具内部问题,大概率 32 位累加器回绕;W=15 会进一步
触发其 modules.py:133 `if ta != 0:` 崩溃)。工具可用上限:激活 16bit +
权重 11bit。

权重只有 11bit 时乘积平均小 32 倍,主表(均匀 16x16 口径)的 MRED 失真,
故 w11/ 下按 a~U[0,65535] x b~U[0,2047] 重新标定了 10 档:
