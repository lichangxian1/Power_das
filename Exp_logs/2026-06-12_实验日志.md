## 1. EDA 基建：两个根因修复（Fix① / Fix②）

### Fix① 真实 STA —— DC 拿不到 pin arrival，改用 PrimeTime
- **问题**：node_timing 里 arrival 全 0、transition 全 NaN，只有 slack 可用。根因：`get_attribute pin arrival/transition` 是 PrimeTime 属性，DC 不填充。
- **方案**：新增 `scripts/pt_sta.tcl`（远程 sandbox_base），跑 PT per-cell STA，输出与 dc_run.tcl 同格式的 NODE_TIMING 块；在 `run_all.sh` 插入 Phase 1.4 调用，覆写 DC 版 rpt。
- **验证**：in_skew 真实（0.0017–0.20 ns，随树深变化）；transition/slack 在内部组合 pin 上仍不可得（nan/inf，次要，接受）。
- 备份：`run_all.sh.bak_pre_pt`。

### Fix② per-cell glitch toggle —— XA 模拟域吃掉了翻转，另开数字门级 SDF 仿真
- **问题**：SAIF 只有 506 字节（仅顶层 clk），node_toggles=0。根因：主功耗流是 XA mixed-signal（`use_spice -cell mult`），compressor 在 analog 域，VCS `$toggle_report` 看不见。
- **方案**：新增 `scripts/run_digital_toggle.sh`——纯数字门级仿真（gate.v + TSMC cell verilog + **SDF MAXIMUM 反标**），复用主流程向量，SAIF 正常抓 ct32/ct22；集成进 `run_xa_vcs.sh:127`，**门控 `DUMP_SAIF=1`**（搜索不触发，只采集时跑）。
- **修掉的关键 bug**：原稿 vcs 同时给了 `+nospecify` 和 SDF 反标——`+nospecify` 禁用 specify 块使 IOPATH 无处反标 = 零延迟 = 抓不到 glitch。改为保留 specify + `+neg_tchk`。
- **验证**（端到端单样本，256 向量）：node_timing **210/210**、node_toggles **210/210**；toggle 计数 358–500 **超过向量数 256** → 每向量多次跳变 = 真实 glitch 被捕获。✅
- 备份：`run_xa_vcs.sh.bak_pre_dtog`。

## 2. 面积预测模型：训练 + evaluate + 瓶颈定论

### 训练与评估（11k 数据，v2_11k_edge10）
| 配置 | 指标（TEST/val） | 结论 |
|---|---|---|
| 默认配置（500ep 平台期杀掉） | val per-N τ≈0.15 | 基线 |
| **mt_strong**（multitask w_delay=0.5 + strong+scale10） | **TEST per-N τ=+0.130**, ρ=0.188, R@10=0.168 | 无提升 |
| GBDT（230 维手工聚合特征） | per-N τ=0.156，**fix-730 τ=0.306** | 与 GNN 打平 |
| GNN 13k 5-fold（6-01 史料） | fix-730 τ=0.29±0.04 | 同水平 |
| N-only 捷径 | mix τ=0.52 | mix τ 几乎全是 N |

ckpt: `outputs/2026-06-12_area_model_mt_strong/`；GBDT: `outputs/2026-06-12_area_gbdt_baseline/`。

### 诊断（数据层分析，v2_11k_edge10）
- N 单独解释 **72.9%** 面积方差 → mix τ 是虚指标。
- 同 N=730 桶（n=2070）：area std 仅 ±0.77%；cell 构成只有 **4 种变体**（196×ct32 + ~15×ct22）→ **同 N 面积差不来自 cell 数量**。
- 同 N 内 **τ(area, delay) = −0.246**（时序越紧 → DC 加大驱动/插 buffer → 面积越大）→ 面积差来自 **DC 时序驱动的 gate sizing**。
- **定论：瓶颈 100% 在特征、0% 在模型**——四种模型全部收敛到 τ≈0.13–0.16；现有结构特征对同 N 面积的信息量已被榨干。对症方向 = 真实 STA 特征。
- 天花板警告：CPA 加法器和 PP 生成逻辑不在图里，这部分 sizing 永远不可见。

## 3. STA/toggle 特征对照实验（snap300 / snap525）

### 数据采集 v1（教训惨痛）
- 首次 16 并发 + MAX_LIMIT=4096 采集被**本机 OOM-kill**（exit 137，共享机内存被挤占）。
- 自愈方案：小批（25/批）+ save_every=1 + resume + 重试 wrapper；**为提速降到 MAX_LIMIT=1024**（← 后证明是错误决定）。
- 采到 **525 样本**，零失败零重复；STA/toggle 覆盖 100%。

### enrich（scripts/enrich_eda_observables.py）
- X 7→**19** 维（8×STA/time_norm + sta_mask + toggle 密度/log + toggle_mask）；edge 5→**12** 维（arrival_gap 等）。

### 对照结果（2×2：power/area × enriched/raw，strong+scale10，5-fold）
| OOF fix-N=730 τ（n=26/折） | enriched | raw | Δ |
|---|---|---|---|
| power | +0.02±0.12 | +0.13±0.14 | −0.11 |
| area | +0.18±0.17 | +0.05±0.13 | +0.13 |

- snap300 预览版的 area Δ=+0.118 在 525 上**未复现**——确认是小样本噪声。
- 方向相互矛盾、std 全覆盖差值 → **判定无效**。

### 关键诊断：是仪器坏了，不是特征没用
1. 同样的 raw 结构特征：11k（4096 向量标签）fix-N τ=**0.70**，新数据（1024 向量）仅 **0.13** → 标签噪声主导。
2. toggle_sum↔power 同 N 相关仅 τ=+0.12（物理上 P_glitch∝toggle 应强相关）。
3. 同 N 内 power 信号 CV 仅 1.8%，1024 向量采样噪声足以淹没。
4. fix-N 桶每折仅 26 个，τ 的 std ±0.12–0.17，统计功效不足。

**结论：MAX_LIMIT=1024 的 525 样本不具裁决能力；observable 特征的真正判决推迟到 4096 向量 + 2000 样本。**

### 顺手发现的工程坑（已记 memory）
- **mode B 陷阱**：样本太少时 stratified batch 的 total_batches=0 → **静默零训练**（Loss=0.0000、指标冻结），不报错。
- **pkill -f 自匹配**：模式含在自己命令行里会把自己杀掉；用 `pgrep -f "xxx[.]py"` 句式规避。
- evaluate 时 default 模式 ckpt 落 `dataset/` 通用名，会被下次运行覆盖——需立刻移入 outputs 目录。
