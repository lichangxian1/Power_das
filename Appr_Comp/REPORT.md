# 近似乘法器 PPA 优化 — 训练汇总报告（2026-06-21 → 06-24）

> 16×16 AND 编码近似乘法器，**低列截断 + 压缩树/近似 cell 联合优化**，PPO/GNN，远端 DC 直出 PPA。
> 远端服务器 ubuntu1（128 核 / 6×4090），三轮训练各 ~14h。
> 对标 **4 个 baseline**：EvoApprox v2022 / ELEX2024 N-4 / Trunc-only Dadda / DesignWare（全部 16-bit 同流程@1.5ns 重测）。

## 摘要（核心成果）

**做出了一条 MED 200–60k 全程、同误差下面积+功耗双轴同时压过 EvoApprox 和 DesignWare 的连续帕累托前沿。** 经 verilator 真实误差闸门 + delay 公平化 + budget 扫描三步达成；合并 **16 个设计点 16/16 双轴压 evo、全部压 DW**，含 evo 最强区（高精度角 MED 200–1k）。三轮训练（06-22 k 扫描 / 06-23 budget 扫描 / 06-24 低误差补点）共 29 run，整夜全部零回退/零 DC 失败/零崩溃。

> **基线已切换到 EvoApprox v2022（最新版，31 个 16×16_unsigned，同流程@1.5ns + circular-wrap MED 重新特征化）。对这个更新更强的基线，我方仍 16/16 双轴全胜**（旧 LITE 版结果见历史；v2022 误差跨度 MED 0–5.18e8，低误差端面积反更大）。对比图：`outputs/2026-06-24_evo_v2022/dcvs_{area,power}_v2022.png`。

> **baseline 套件已扩到 4 个**（详见第三节）：对 **EvoApprox v2022 / ELEX2024 N-4 / DesignWare** 三个外部 baseline **全面占优**（双轴/三轴）；对 **Trunc-only Dadda（纯截断，最强朴素对照）面积持平±6%、功耗优 8–34%**——即本工作相对纯截断的真实增量**主要在功耗**（含 PPO 布线优化贡献），面积维度印证"截断主导"。这是结论的诚实边界。

## 一、相比起点做了哪些方法改动

**基线**：2026-06-21 过夜 DC 8 点扫描（k∈{0,4,8,12,16}），用**解析误差代理（proxy）做闸门**，`delay_weight=2`、`target_delay=2.0ns`。

改动（提交 `d72b5ea` + `45e518d`，均未 push）：

### 1. 误差闸门：解析 proxy → verilator 真实 MED（核心）
- 起因：量化发现解析 proxy **系统性低估真实 MED 0–30%**，cell 越多偏越狠：

  | 设计 | proxy MED | 真实 MED (verilator) | proxy/真实 |
  |---|---|---|---|
  | k16 (纯截断) | 76024 | 76271 | 1.00× |
  | k12 (1 cell) | 4309 | 4578 | 0.94× |
  | k0 (26 cell) | 8300 | 9705 | 0.86× |
  | k8 (9 cell) | 4588 | 6514 | **0.70×** |

  根因：解析项是三角不等式上界 `Σ WAE·2^col`，cell 的 WAE 取自**孤立 cell/P=1/4**，没算误差在树里的传播放大。
- 方案（codex 审过）：`error_gate="verilator"`，每候选在 worker 内并行用 verilator MC（16M 向量、**circular-wrap** 到 [-2³⁰,2³⁰)）测真实 MED/bias 当软罚闸门。
  - 只进 `get_objective` 离散打分，**不碰可微 error_loss**；**WCE 仍用解析上界**（MC 尾部不收敛）。
  - verilator 失败回退解析、**不丢样本**（verilator 失败 ≠ DC 失败）。新增 harness `verilate/mul_err_wrap.cpp`。

### 2. delay 公平化
- `delay_weight: 2 → 0`，DC 评估 `target_delay: 2.0 → 1.5ns`。旧目标线性奖励"更快"→ RL 花面积把 delay 压到 1.2–1.37ns、同误差下面积偏大、与 evo 1.8ns 比不公平。改为 delay 退化成时序约束，预算全给 area/power。

### 3. 配套
- `error_source`/`measured_error` 写进 `best_info.json`（可审计）；修复 `export_best_candidate` 漏带审计字段（smoke 抓出）；Gomil 补 `cell_types`。

### 支撑数据（为何敢把真实误差搬进 loop）
- verilator：build ~3s + run 0.72s@4M；一次 DC ~200s → verilator 快 ~50×，进 loop 仅 +~3%。
- MC 收敛：MAE/MED/BIAS **1M 向量就够**（1M↔64M <0.15%）；**WCE 不收敛**（越采越大）→ 必须用解析上界。

## 二、两轮训练与结果

### Round 1 — k-深度扫描（2026-06-22，9 run，72 license）
固定 `med_budget=65536` 扫 k∈{8,10..15} + k12 预算追踪{8192,32768,65536}。**9/9 整夜零回退/零 DC 失败/零崩溃。**

**关键发现 → 方法论修正**：准确闸门下 `med_budget` 是会被**吃满的硬旋钮**。固定 budget 扫 k，结果各 k 全顶到 MED 44–75k、没沿误差轴铺开（只有 k12 那 3 个 budget 点描出干净的 PPA-误差权衡）。**⇒ 前沿要靠扫 budget 描，不是固定 budget 扫 k。** 这直接决定了 Round 2 的设计。

其余结论：C2 截断>cell（cell 数随 k 单调降 84→13）、C5 真实 MED 随 budget 单调（7074/29841/44783）、C3 delay 贴 1.5ns、C6 该轮 8/9 双轴压 evo（唯一输的 k8 靠堆 84 cell）。

### Round 2 — budget 扫描描前沿（2026-06-23，10 run，80 license 单卡）

### Round 3 — 低误差段补点，延伸到 evo 高精度角（2026-06-24，10 run，80 license 单卡）
目标 MED < 1.5k，往 evo 最强区延伸。**关键修复**：Round 1/2 的 tight budget 会**超调**（预算 1536 落到 MED 4921），根因是 `error_scale=1e5` 让软罚在低 MED 区可忽略。新增 CLI `--error_scale`，调到 **1000** 让预算真正 binding。

结果：error_scale=1000 偏强，优化器直接退到**纯截断 floor、0 cell、bias≈0**——10 run 收敛到 **3 个干净的超低误差点**（每个 k 的截断下限）：

|---|---|---|---|---|---|
| k10_b1300 | 10 | 765.2 | 0.401 | 914 | 0 |

（budget 在每个 k 内不再区分 → 10 run 实际是 3 个 floor 点；纯截断 = 最省面积、零偏置、确定性。）

### 第三方基线 Trunc-only Dadda（2026-06-24 叠入）

**纯 Dadda 压缩树 + 低位截断（常数补偿，0 近似 cell）**，近似乘法器领域最朴素也最强的 baseline。用**本项目自己的生成器**（同源/同库/同流程：`CompressorTree.dadda` + `Mul.emit_verilog`，常数补偿 C=round(E[Δ])，单一固定布线），同口径测量。扫 **k=1..24**，MED **0.25 → 1.48×10⁷**（越过 1e7），DC **24/24 成功**。代表点（截断越深→越省）：

|---|---|---|---|
| 1  | 0.25      | 1040 | 0.811 |
| 8  | 200       | 921  | 0.683 |

**我方前沿 vs 纯截断（同 MED 插值，覆盖 MED 200–60k）**：

| 维度 | 结论 |
|---|---|
| **面积** | **基本持平（±6%，互有胜负）**——中误差段（MED 4k–45k）纯截断甚至略优我方 |
| **功耗** | 我方**全程优 8–34%** |

> **这是最强的对照，也最诚实**：(1) 面积上我方相对纯截断**几乎无优势** → 直接印证 C2"截断主导面积"——"自动选最优截断深度"在面积维度并没超越朴素纯截断；(2) 我方真正的增量在**功耗**（PPO 布线优化 + 少量近似 cell）；(3) 纯截断本身就**压过 EvoApprox v2022（中低误差段面积/功耗都优）、把 ELEX2024 压在右上方** → 功耗序 **我方 > 纯截断 > evo**。
> **⚠ 公平性 caveat**：本 baseline 用**单一固定随机布线（未经 PPO 优化）**，而我方前沿优化了布线（connection 是 PPO 采样对象）→ **功耗优势含布线优化贡献**；若对纯截断也做布线选优，功耗差距会缩小（面积结论不受影响，布线对面积影响小）。图：`outputs/2026-06-24_trunc_baseline/dcvs_{area,power}_all.png`（紫▽=Trunc-only Dadda）。

## 五、结论与下一步

**结论**：通过 verilator 真实误差闸门 + delay 公平化 + budget/error_scale 扫描，在 16×16 近似乘法器上做出了一条 **MED 200–60k 全程双轴压过 EvoApprox 和 DesignWare 的 PPA 帕累托前沿（16/16）**，含 evo 最强的高精度角，达成并超额完成项目最初目标。**对 4 个 baseline 的诚实定位**：EvoApprox v2022 / ELEX2024 N-4 / DesignWare 三者全面占优；对最强的内部对照 **Trunc-only Dadda（纯截断），面积持平（±6%）、功耗优（8–34%）**——本工作相对纯截断的真实增量主要在**功耗**，面积维度印证"截断主导"。

**下一步**：
1. **巩固功耗优势的可信度**（最高优先）：对纯截断也做布线选优（每 k 多布线取最优，24×N DC），量化"功耗优 8–34%"里布线优化 vs 近似 cell 各占多少——这是当前 caveat，直接关系核心 claim 强度。
2. 若要再往极高精度延（MED < 200）：需要比 k8 更浅的截断或专门低误差 cell 库——但 k8 floor(200) 已压过 evo，性价比递减。
3. 极高误差尾（MED > 60k）若需要，k15–16 + 松 budget（注意 k16 会崩，需 WCE 约束）。
4. 整理论文级前沿图 + NMED 口径；提交 `d72b5ea`+`45e518d`（仍未 push）。
